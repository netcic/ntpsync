# 局域网 NTP 授时系统

> 无外网局域网内的 NTP/SNTP 授时工具。服务端以本机硬件时钟为权威时间源，向交换机、服务器、
> 工控机等标准 NTP 客户端授时；客户端（及设备）校时收敛到服务端。
>
> 跨 **Windows / Linux / 国产操作系统**，覆盖 **x86 + ARM** 架构，支持**企业静默批量部署**，
> 附带 **Motrix 风格**的 Web 图形管理界面。

> **产品命名（1.10.28 起）**：服务端发布名 **Sntpserver**、客户端 **SntpClient**；所有分发产物
> 文件名一律带版本号（如 `Sntpserver-v1.10.28-windows-amd64.exe`），不再产出无版本副本。
> 安装目录 `%ProgramFiles%\Sntpserver` 与 `%ProgramFiles%\SntpClient`，系统服务名同名；
> 配置与日志仍在 `%ProgramData%\ntpsync`（Windows）/ `/etc/ntpsync`（Linux），升级可沿用旧配置。

## 一、特性

| 能力 | 说明 |
|------|------|
| **纯离线授时** | 不依赖任何公网 NTP（pool.ntp.org 等），服务端时间源 = 本机硬件时钟 |
| **标准协议兼容** | 服务端发送 RFC 5905 合法报文，兼容 w32tm、chrony、ntpd 及交换机等 SNTP 设备 |
| **跨平台** | Windows 7/10/11/Server、主流 Linux、国产 OS（UOS/麒麟等，基于 Linux 内核） |
| **双架构** | x86_64 + ARM64（含 Apple Silicon、树莓派、国产 ARM 平台） |
| **图形界面** | Motrix 风格 Web 管理界面（服务端 + 客户端各自内嵌），深色卡片式 |
| **静默部署** | 装成系统服务（开机自启），配合 GPO / SCCM / Ansible 铺开 |
| **单二进制** | Go 静态编译，无运行时依赖，单文件分发（服务端约 6M、客户端约 2M） |
| **校时护栏** | 大偏差拒绝盲跳，防服务端时钟错误污染全网 |

## 二、整体架构

```
┌─────────────────────────────────────────────┐
│  图形界面 (Web UI，Motrix 风格，go:embed 内嵌) │  服务端面板 / 客户端面板 / 设置 / 日志
├─────────────────────────────────────────────┤
│  应用层 (Sntpserver 服务端 / SntpClient 客户端)      │  配置、调度、生命周期、装服务
├─────────────────────────────────────────────┤
│  NTP 核心 (64位时间戳 + RFC5905 报文编解码)     │  与 OS 无关，可单测
├─────────────────────────────────────────────┤
│  网络层 (UDP 123 监听 / 客户端请求)            │  超时、重试
├─────────────────────────────────────────────┤
│  平台抽象层 PAL (读钟 / 设钟 / 提权 / 装服务)   │  Windows / Linux·国产 两套实现
└─────────────────────────────────────────────┘
```

- **服务端 `Sntpserver`**：读本机硬件时钟 → 构造合法 NTP 报文 → UDP 123 常驻监听，可注册为系统服务自启。
- **客户端 `SntpClient`**：向服务端请求时间 → 计算时钟偏差 → 在护栏允许范围内修改本机系统时钟，支持单次 / 常驻后台两种模式。

## 三、快速开始

### 3.1 选一台机器作服务端（时间源）

> ⚠️ **先对时**：整个局域网的"准"取决于服务端硬件时钟。启动前请先核对服务端本机时间（可用手表 /
> 手机 / 其他可信源），确保服务端时间正确。服务端本机改钟需管理员权限。

**Windows（管理员运行）**

```bat
:: 前台运行（调试用，Ctrl+C 退出），同时启动 Web 界面
Sntpserver.exe run -l 0.0.0.0:123 -web 127.0.0.1:8080

:: 或注册为系统服务并开机自启
Sntpserver.exe install -l 0.0.0.0:123
```

**Linux / 国产 OS（root）**

```bash
# 前台运行
./Sntpserver run -l 0.0.0.0:123 -web 127.0.0.1:8080

# 或注册为 systemd 服务
./Sntpserver install -l 0.0.0.0:123
```

### 3.2 客户端 / 设备校时

**用本系统客户端（Windows / Linux 机器）**

```bash
# 先只测偏差（安全，无需提权）
SntpClient check -s 192.168.1.10:123

# 单次校时（需管理员/root）
SntpClient sync -s 192.168.1.10:123

# 常驻后台周期校时（需管理员/root，默认每 15 分钟）
SntpClient daemon -s 192.168.1.10:123
```

**交换机 / 路由器 / 其他标准设备**

直接在设备的 NTP 配置里把服务器地址指向服务端 IP 即可，无需安装任何客户端。

> 详细静默安装、批量推送、防火墙配置见 [`DEPLOY.md`](DEPLOY.md)。

## 四、命令行用法

### 服务端 `Sntpserver`

| 子命令 | 说明 |
|--------|------|
| `run [-l ADDR] [-s STRATUM] [-web ADDR] [-upstream ADDR]` | 前台运行（可启 Web 界面 / 向上游同步） |
| `install [-l ADDR] [-s STRATUM] [-web ADDR] [-upstream ADDR]` | 注册为系统服务并自启（需提权） |
| `uninstall` | 卸载系统服务（需提权） |
| `start` / `stop` / `status` | 启动 / 停止 / 查询系统服务 |

| 参数 | 默认 | 说明 |
|------|------|------|
| `-l` | `0.0.0.0:123` | 监听地址 |
| `-s` | `2` | NTP 层级（stratum，本机时钟作源一般取 2） |
| `-web` | 空 | Web 界面监听地址，如 `127.0.0.1:8080`，留空不启用 |
| `-upstream` | 空 | 上游 NTP 时间源（如 `ntp.aliyun.com`），留空则用本机硬件时钟 |
| `-upstream-interval` | `1小时` | 向上游同步的间隔（支持 `30分`/`2小时`） |
| `-config` | 系统标准路径 | 配置文件路径，便于多实例与测试隔离 |
| `-manual` | false | `install` 时仅安装服务不自动启动 |
| `-no-firewall` | false | `install` 时跳过防火墙放行 |

> **上游时间源说明**：配置了 `-upstream` 后，服务端会周期性向上游 NTP 校时，把本机时钟锚定到
> 上游，再向局域网下游授时。留空则维持默认——以本机硬件时钟为权威源，不依赖外网。

#### 上游服务器选择（实测建议）

公网上游的可靠性差异极大，实测同一台机器上的成功率：

| 上游 | 实测往返 | 可用性 |
|------|---------|--------|
| `ntp.aliyun.com` | 46–55 ms | ✅ 稳定 |
| `cn.pool.ntp.org` | 20–22 ms | ✅ 稳定 |
| `time.windows.com` | 114 ms | ✅ 稳定 |
| `ntp.ntsc.ac.cn`（国家授时中心） | — | ⚠️ 间歇性失联，仅约 20% 请求有响应 |

`ntp.ntsc.ac.cn` 解析出 3 个 IP，其中 2 个长期无响应，剩下 1 个丢包率也高达约 75%。
**不建议作为生产上游**；如必须使用国内权威源，建议改用 `ntp.aliyun.com` 或 `cn.pool.ntp.org`。

客户端已内置多地址并发探测与丢包重试：域名解析出多个 IP 时会同时探测、取最快响应，
单个 IP 超时则自动重试，因此部分节点故障不会导致整体失败。

#### 配置文件与参数优先级

服务端把运行配置持久化到 JSON 文件，Web 参数页保存时自动写入：

| 平台 | 路径 |
|------|------|
| Windows | `C:\ProgramData\ntpsync\ntpsyncd.json` |
| Linux | `/etc/ntpsync/ntpsyncd.json` |

优先级：**命令行显式参数 > 配置文件 > 内置默认值**。文件不存在时一切按命令行/默认值运行，
因此既有静默部署脚本不受影响。

从本版本起，`install` 会把配置写入该文件（而非塞进服务启动命令），避免「Web 上改完、
重启后被安装参数覆盖」。Web 参数页修改**上游地址/同步间隔**会立即生效，无需重启；
**监听地址/层级**需重启服务。

### 客户端 `SntpClient`

| 子命令 | 说明 |
|--------|------|
| `check -s ADDR` | 只测偏差/时延，不改钟（安全，无需提权） |
| `sync -s ADDR [-step D]` | 单次校时（需提权） |
| `daemon -s ADDR [-interval D] [-step D] [-web ADDR]` | 常驻后台周期校时（需提权，可启本地 Web） |
| `install -s ADDR [-interval D] [-step D] [-web ADDR]` | 注册为系统服务自启（需提权） |
| `uninstall` / `start` / `stop` / `status` | 服务管理（只操作本程序自己的服务：`SntpClient`） |

| 参数 | 默认 | 说明 |
|------|------|------|
| `-s` | 必填 | 服务端地址，如 `127.0.0.1:123` |
| `-step` | `5秒` | 校时阈值：单次允许的最大跳变幅度，超过则拒绝自动设钟（支持 `5秒`/`30秒`/`1分`） |
| `-interval` | `15分` | 后台校时间隔（支持 `15分`/`30秒`/`1小时`，纯数字按「分」） |
| `-web` | 空 | 本地 Web 界面地址，如 `127.0.0.1:8090`，留空不启用 |

> 时间参数同时兼容英文标准格式（`15m`/`5s`/`1h30m`），中英文均可。

客户端配置同样落盘（与服务端分文件，避免同机双端互相覆盖）：

| 平台 | 路径 |
|------|------|
| Windows | `C:\ProgramData\ntpsync\ntpsync.json` |
| Linux | `/etc/ntpsync/ntpsync.json` |

优先级与服务端一致：**命令行显式参数 > 配置文件 > 内置默认值**。
`install` 把校时目标/间隔/阈值写进该文件（不再塞进服务启动命令），
Web 参数页保存后**立即生效**（守护循环当场按新间隔重排，状态总览同步刷新），
`install` 注册的服务重启后仍按保存值运行。

> Windows 安装器（`/INTERVAL` `/STEP`）与 `install` 写的是**同一个配置文件**，不是
> 服务启动命令（启动命令恒为 `SntpClient daemon`）。因此安装参数只是初始值，之后在 Web 里
> 改完即时生效并落盘，重启后依旧生效。
>
> 覆盖升级安装时，安装器检测到已有配置文件会自动加 `-preserve`（保留原有参数、只重新
> 注册服务）；要强制按安装参数重建配置，静默安装时显式带上参数即可。

## 五、Web 管理界面

服务端与客户端**各自内嵌**一套 Web 管理界面（同一套深色卡片式 UI，按角色自适应显示）：

- **服务端**：`Sntpserver -web 127.0.0.1:8080` 启动后，访问 `http://127.0.0.1:8080`，
  展示授时状态（监听地址及本机可用 IP、层级、请求计数、最近客户端）+ 用户列表 + 设置 + 日志。
  服务端不向他人校时，故不提供「校时工具」面板。
- **客户端**：`SntpClient daemon -web 127.0.0.1:8090` 启动后，访问 `http://127.0.0.1:8090`，
  展示本机校时状态（校时目标、间隔、最近偏差/时延/结果）+ 校时工具 + 设置 + 日志。

| 面板 | 功能 |
|------|------|
| **总览** | 实时时间核对、运行状态（服务端显示授时 / 客户端显示校时守护） |
| **用户列表** | 仅服务端：最近授时的客户端 IP、授时次数（同一 IP 合并一行并累加）、首末时间（每页 15 条） |
| **校时工具** | 仅客户端：一键"检测偏差 / 立即校时"，即时显示结果 |
| **设置** | 客户端：服务端地址、校时间隔、校时阈值；服务端：监听地址、层级、上游时间源与同步间隔（含「立即同步」按钮） |
| **日志** | 环形日志缓冲，实时查看运行记录 |

> 默认只绑定 `127.0.0.1`（仅本机访问）。如需远程访问请改绑 `0.0.0.0` 并放行对应 TCP 端口。

**配色主题**：侧栏底部「配色主题」可一键切换「默认（蓝）/ 暖橙+深灰 / 海军蓝+渐变」三套配色，
选择记在浏览器本地（localStorage），下次打开沿用。主要按钮带悬停变色 + 放大效果。

## 六、校时护栏说明

客户端改钟前按以下顺序把关，防止误操作或服务端时钟错误污染本机：

```
测偏差 → 超阈值(默认5s)？  → 拒绝盲跳，需人工确认
       → 偏差 < 1ms？     → 无需修改，不动作
       → 未提权？         → 明确报错引导（提示用管理员/root）
       → 通过              → 提权设钟落地
```

- **阈值可用 `-step` 调**：偏差超过阈值时拒绝自动改钟，避免服务端钟错导致全网时钟大跳变。
- **`check` 永远安全**：只测不改，任何权限下都能跑，适合日常巡检。
- **服务端向上游校时不设阈值**：服务端本身就是全网的权威时间源，面对上游没有更高的权威可依，
  因此偏差多大都会直接设钟（否则首次部署、CMOS 电池失效、虚拟机长期休眠造成的十几秒偏差
  会被永久挡在护栏外）。护栏只作用于「客户端 → 服务端」这条链路。

## 七、常见问题 FAQ

**Q1：服务端时间是怎么来的？会不会越校越偏？**
默认以本机硬件时钟为权威时间源，不做上游对时；配置了上游时间源（`-upstream`）后，服务端会
按间隔向上游校时并修正本机时钟，再向下游授时。前者要求启动前人工核对服务端时间，后者则由
上游保证准确性。

**Q2：客户端校时提示"未提权"，怎么办？**
改系统时钟需要管理员权限。Windows 用管理员运行，Linux 用 `sudo` / root 运行。`check`（只测不改）无需提权。

**Q3：偏差超过 5 秒，校时被拒绝了？**
这是护栏在保护你——大偏差可能意味着服务端时钟错误。确认服务端时间无误后，可用 `-step` 放宽阈值，或人工核对后再校。

**Q4：交换机 / 标准设备能用吗？**
能。服务端发送 RFC 5905 合法报文，w32tm、chrony、ntpd 及交换机 SNTP 客户端均可直接指向服务端授时。

**Q5：需要连外网吗？**
完全不需要。二进制为 Go 静态编译，无任何运行时依赖，离线分发即可运行。

**Q6：国产操作系统（UOS / 麒麟）支持吗？**
支持。国产 OS 基于 Linux 内核，走 systemd 服务管理（含 SysVinit 兜底），ARM64 / x86_64 均覆盖。具体版本建议按 [`TESTING.md`](TESTING.md) 实测确认。

**Q7：服务端能同时服务多少客户端？**
服务端为单线程非阻塞 UDP，实测 100 并发下吞吐约 7500 req/s，单局域网规模轻松覆盖。

## 构建

开发环境需 Go 1.23+。一键交叉编译全矩阵：

```bash
bash scripts/build.sh
```

版本号统一写在根目录的 **`VERSION`** 文件里（当前 `1.10.28`），构建、打包、安装器、
Windows 版本资源全部从它读取，升版只改这一处。需要临时编一个别的版本时把版本号
作为参数传入即可覆盖：`bash scripts/build.sh 1.10.29`。

产物输出到 `dist/`，覆盖 Windows / Linux × amd64 / arm64 共 8 个二进制，文件名一律带版本号：`Sntpserver-v1.10.28-windows-amd64.exe`、`SntpClient-v1.10.28-linux-arm64` 等；不带版本号的旧式副本不再产出。

## 打包独立安装程序

编译产物是「裸二进制 + 安装脚本」，为了分发方便，可再打包成各系统的独立安装程序：

**Windows 安装器**（GUI 向导 + `/S` 静默，需先装 NSIS）：

```bash
scoop install nsis            # 一次性安装 NSIS
scripts/build-installers.bat
```

产出 4 个安装器：`Sntpserver-setup-*` / `SntpClient-setup-*` × amd64/arm64，双击即装、控制面板可卸载。

**Linux 原生包**（`.deb` + `.rpm`，需在 Linux 机上运行）：

```bash
# 在任意带打包工具的 Linux 机（Debian/Ubuntu 装 dpkg，红帽/麒麟装 rpm-build）：
CLIENT_SERVER=192.168.1.10:123 bash scripts/package.sh
```

产出服务端/客户端 × amd64/arm64 × deb/rpm，`dpkg -i` / `rpm -i` 安装即自启。

**打包自检**（没有 dpkg/rpm 也能验）：先在任意机器生成待校验目录树，再做字段级校验，
能在「还没到 Linux 打包机上」就发现 control 字段、spec 的 `%files`、systemd 单元
参数写错这类问题：

```bash
bash scripts/package.sh --dry-run    # 生成 dist/pkgstage/
bash scripts/check-stage.sh          # 校验元数据与单元文件，全过才继续
```
